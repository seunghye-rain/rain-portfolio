# git-commit

```txt
변경사항을 커밋 단위로 나누고 커밋 메시지를 작성합니다. "커밋해줘" 요청을 받았거나 변경사항을 정리해서 커밋해야 할 때 사용합니다.
```

# 커밋

## 스킬 설명

`docs/conventions/commit.md` 기준으로, 스테이징된 변경사항을 의미 있는 단위로 나누고 형식에 맞는 커밋 메시지를 작성하는 작업입니다.

## 참조 문서

| 문서                         | 참조 내용                                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| `docs/conventions/commit.md` | 접두사 표, 메시지 형식, 커밋을 나누는 5가지 기준, 커밋 절차 (이 스킬의 규칙은 전부 이 문서에서 옵니다) |

## 트리거

- "커밋해줘", "커밋 만들어줘"
- "변경사항 나눠서 커밋해줘"

## 해야 할 일

`commit.md`의 커밋 절차를 그대로 따릅니다.

1. `git status`, `git diff`로 전체 변경사항을 확인합니다.
2. `commit.md`의 기준으로 변경 파일을 그룹으로 나눕니다. (같은 scope끼리 묶기 → 접두사가 다르면 분리 → 자동 포맷팅성 변경은 별도 커밋 → 문서 갱신은 코드 변경 범위에 따라 함께/분리 판단)
3. `.env`, 비밀번호, API 키, 토큰처럼 커밋되면 안 되는 파일이 스테이징되어 있는지 먼저 확인합니다. 있으면 즉시 멈추고 알립니다.
4. 그룹별로 필요한 파일만 `git add`한 뒤 커밋합니다. `git add -A`로 한 번에 올리지 않습니다.
5. 각 커밋 메시지는 `{접두사}: {제목}` 형식으로 쓰고, 필요하면 본문에 "무엇을/왜"를 남깁니다.
6. 사용자가 명시적으로 요청하지 않았다면 커밋까지만 하고 push는 하지 않습니다.

## 점검해야 할 내용

- 커밋 메시지가 `commit.md`의 접두사 표와 형식(제목에 마침표 없음)을 따르는가?
- 서로 다른 관심사가 한 커밋에 섞이지 않았는가?
- `.env`나 비밀값이 포함되지 않았는가?
